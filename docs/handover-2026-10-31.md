## 二、已排除（别再排查）

| # | 结论 | 依据 |
|---|---|---|
| E1 | 这个内核**没有 nanosleep 系统调用** | `sysent` 表：240 = `_listxattr`；0–600 内无 nanosleep；睡眠要用 93 `_select` |
| E2 | `/dev/console` **不是**视频控制台 | 写入不可见；面板从内核内部直接画才可见 |
| E3 | `cpus=1` 下父进程自旋会饿死子进程 | clover 75–77 轮；父进程必须阻塞 `wait4` |
| E4 | `panic_screen` 与 stage-4 探针不能共存 | padding 0x970 < panic 屏 0x9f5 |

## 四、N4KROOT 镜像格式（mockfs-test-file.patch 校验）

```
<8s "N4KROOT\0"> <I version=1> <I count=2> <Q launch_offset=4096>
<Q launch_size> <Q test_offset(>=8192,4K 对齐)> <Q test_size>
设备 ≤ 32 MiB；launch_size>0；test_size>0；launch_size ≤ test_offset-4096
```
裸 Mach-O 不行——第一字节不是 `N4KROOT` 会走旧 adopt 分支、静默挂起。

## 五、观测通道（按可靠性排序）

1. **BootProgressMin 面板**（`boot-progress=2`，内核内直接画 framebuffer）：最好用，逐行打印 bsd_init 阶段
2. **`reboot(RB_PANIC|RB_QUICK, msg)`**（x16=55, x0=0xc00, x1=NUL 字符串）：可写一整句话
3. **退出码**（panic 屏 `initproc failed to start ... exit status N`）：只有 8 位，容易被屏幕换行截断
4. **stage-4 探针**（`entry_probe_reset_delay=6` + `--reset-after`）：二进制判据，需与 panic 屏二选一
