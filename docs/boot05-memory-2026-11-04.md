# K70 boot05：受检 RAM 扩展与持久失败显示

boot04 已在 K70 真机进入 XNU/bsd_init，最后因缺少根设备而停止。boot05 尝试从实际传入的 FDT 中发现额外 RAM，为后续系统签名表和驱动提供 512 MiB 窗口；它沿用已知内核，没有携带 OS 根卷。

原 boot05 的真机照片仅确认菜单返回 `Compromised Data`。菜单重绘覆盖了精确原因。boot05r1 仅补持久失败画面，显示精确拒绝原因或失败阶段、状态以及已验证 FDT 的有界元数据计数；释放全部按键约一秒后，再按新键才返回菜单。

boot05r1 已写入 boot_b，发送、写入和重启均为 OKAY。随后本机照片明确显示：

```text
M05 no measured 514MiB contiguous GCD gap
STATUS Compromised Data (0x8000000000000021)
META 0 BANKS 8 RESV 52 DYN 0
FDT PA B3DFE000 BYTES C593C
```

这证明实际运行时 FDT 有非零 RAM 信息，且解析成功。当前停止点是内存规划器未找到符合其条件的连续区域，发生在发布新 RAM 和执行 XNU 之前。它不证明手机实际内存不足，也不能证明内存映射或 XPU 访问已经失败。下一步核查实际内存表、GCD 类型及排除条件；512 MiB 窗口仍未在真机建立。

RAM 计划只接受 FDT 的非零 `memory/reg`，只使用与当前 GCD `NonExistent` 的交集，排除所有 FDT 保留区及活跃输入。它不会把 boot04 的四块未知保留区改为可分配 RAM，不启用旧 BootMemoryDxe 或 OEM 不可靠的固定范围回退。真实 WB 映射先于 GCD 提交；提交部分失败后保留可能已使用的映射和 RAM，拒绝本次固件会话内重试。

r1 的 RAM 代码、内存表、入口汇编、内核和 ADT 均与原 boot05 相同。原 boot05 完整 EDK 构建成功；r1 的新 DarwinBoot 已实际完成编译和链接，重复编译依赖的全目标构建随后被取消并明确记为失败。最终容器使用 48 项受检的未改 PE 和 serial GenFds 重新生成，完整 FD 审计与 Android 镜像解包回读均通过。PCD 模块重链接只改变 RSDS 调试 GUID，已核对其余字节及原始 PCD 数据库后恢复原完整构建的精确 PE。
