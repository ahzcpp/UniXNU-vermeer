# boot05r2：真实内存区间与同一 GCD 区域内的相邻片段

r1 真机画面明确显示 `M05 no measured 514MiB contiguous GCD gap`、`META 0 BANKS 8 RESV 52 DYN 0`。这证明实际传入 FDT 的解析成功且有 8 个非零 RAM bank，不能据此宣称手机物理内存不足，也不能直接释放旧占位保留区。

r2 在完成全部 FDT 保留区和活跃输入排除后，将相邻合格片段规范化。只有 `End == Base` 且合并后的完整范围仍属于同一个原始 `NonExistent` GCD 描述符才允许合并；最终发布前的 GCD 类型、所有权及完整范围复查保持不变。四个占位 MemoryMap 描述符、其 HOB、入口汇编、内核和 ADT 均未改动，没有 `FreePages`、重分类或物理探测。

该改动针对已确认的源码问题：原规划器对每个 FDT bank 单独输出片段，512 MiB 的相邻 bank 即使属于同一合格 GCD 范围，也会分别低于 514 MiB 阈值。尚不知道这是不是本机 r1 拒绝的实际原因。ASan/UBSan 的 3000 轮逐页集合对照证明规范化前后字节集合相同，另覆盖相邻 512 MiB、不同 GCD 边界、间隔页和重叠拒绝；实际生产发布器模型也通过相邻两个 512 MiB FDT reg 项及原失败/禁止重试测试。

如果仍拒绝，r2 保留一张两列画面：左列是实际 bank、各类 GCD 覆盖字节、最大原片段/同 GCD 合并片段、占位区的 GCD/所有权/HOB/EFI 类型；右列列出所有 52 个 FDT 保留范围。`U0..U3` 的 `HOB R/A/X` 分别表示精确匹配的 SYS_MEM resource HOB、精确匹配的 Reserved allocation HOB、其他重叠 HOB 数；`EFI0` 表示整个占位区仍由 EFI ReservedMemoryType 覆盖。它们是下一步源码归属判断的证据，不会自行修改内存图。

原厂/当前源码显示，`MemoryInitPei.c::AddHob` 对 SYS_MEM 不论 HobOption 都建立 allocation HOB。因此只把四个占位的 AddMem 改成 NoHob 仍不能生成可发布空洞。下一步是否从独立 SEC profile 移除特定占位描述符，必须以本轮实际范围为依据，当前未实施。

完整镜像 SHA-256：`c0724bef6c62b504850264bbbff438fec8b78b045e260b9b5c4da1d824ae4c86`，68,665,344 字节；FD SHA-256：`2fdea384c5b94fde539fabd3f9a7370caf3372d9c667a5fbb90fc1a2548677f9`。模块编译/链接、serial GenFds、完整 FD 审计及 Android/FAT/FD/DTB 解包回读通过。已刷入 boot_b 并重启，均返回 OKAY；镜像没有 OS 根卷。

真机 r2 停在范围画面：`BANKS 8 RESV 52 GCD 55`，`STRICT RC 0 N 0 GAP 21`，`MAX PIECE 0 JOIN 0`。R31–R47 包含多条 `0–FFFFFFFF`、`100000000–FFFFFFFFFFFFFFFF`，以及 `0–FFFFFFFFFFFFFFFF`，覆盖所有候选 RAM。四个占位区均显示 `HOB R1 A1 X0` 和完整 EFI Reserved 覆盖；本轮没有发布新 RAM，没有进入 XNU。

对照源码和 [Devicetree reserved-memory 规范](https://github.com/devicetree-org/dt-schema/blob/main/dtschema/schemas/reserved-memory/reserved-memory.yaml)，已定位到原解析器把 `alloc-ranges` 的允许分配范围加入了实际 Reserved 列表。`size` 无 `reg` 的节点是动态申请，不能把整个允许范围当成已经占用。下一版会核对具体节点及当前启动链中的分配语义；实际 `reg`、FDT reserve map、固件占用和活跃输入仍须排除。当前补丁保留 r2 实际测试源码，尚未包含此后续修复。

本增量补丁应用在 `boot05-memory-source.patch`（SHA `588a60d1f22f45ba53a16596be18d2995a953f0cd0b18e9737a297fca884bb71`）之后。它更新当前运行时源码；原 r1 的历史报告保留，r2 的报告在 `r2/` 下。仍使用原 README 的固定本地工作区和已有受检输出，不附带任何 Apple/OEM 二进制或私有手机标识。
