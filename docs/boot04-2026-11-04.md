# K70 boot04：继续内核入口定位

用户要求暂停 USB 检测后，继续从已知 trace02 启动路径排查。本轮没有
刷写手机。当前 boot_b 仍是前一轮 USB 诊断构建，其屏幕状态未确认；
原厂 vendor_boot_b 保持此前恢复后的内容。

boot04 只使用原厂 DXE Heap `0xBAB00000..0xC7CC0000`，将四个未经本机
确认的 gap/high bank 保留，移除动态添加内存的驱动。专用 DarwinBoot
使用显式 128 MiB 窗口，保持 256 MiB 默认值，不回落其他物理地址。
读取负载前核对真实 HOB/FDT/initrd，发现与堆冲突或未保留输入即拒绝。
这不能证明更早的 UEFI 内存分配已安全，也不提供完整系统内存预算。

实际 trace02 Mach-O 字节复核确认：入口 `0xfffffff00741e488` 的
`1400001e` 正确跳到 `0xfffffff00741e500`，固定蓝条探针的 44 字节
均有可执行 segment 文件字节支持，随后跳到 `_start_first_cpu`
`0xfffffff00742005c`。没有发现文件/VM 偏移错误。内核入口仍未获真机证明。

真实分配器及输入检查通过 ASan/UBSan，包含 163,840 个边界参考用例和
bundled libfdt 测试。完整 EDK 构建 exit 0，运行时源快照未变；FD 审计
核对了模块唯一性、PE/TE 来源及 MemoryMap 源数据到最终 SEC 的绑定。
完整 boot 已独立解包，对比 FD、FAT、内核和 ADT。详见
[验证摘要](boot04-verification-2026-11-04.json)。这些都是离线证据。

源码见仓库根的 `boot04-system-source.patch` 和对应 manifest。补丁只
创建 `research/boot-chain-04` 与 `research/system-build`，不包含 Apple
或 OEM 二进制；已在空仓库完成 apply/check 及全部文件逐字节读回。
应用后阅读各目录 README；脚本依赖固定的现有构建工作区，不是通用
一键构建器，基线工作流不会自动采用此实验。
