K70 storage packager v2, 2026-11-04

This is a narrow repeated-use fix. It does not invalidate the already checked
storage-native-01 boot container, and it changes no kernel, payload, firmware,
phone partition, original v1 script, original verification report, or frozen
source-only ZIP.

Problem fixed

The v1 script checked an explicit FD SHA and later reopened that source path
for building/unpacking/reporting. Replacing the source file during that interval
could detach the bytes actually used from the explicit input identity. Its report
also referred to boot-chain-05/fd-audit.json, which a later firmware audit replaces.

package-storage-boot-v2.py reads each original FD/audit input once, verifies their
matching identity, and writes those exact captured bytes to a fresh artifact's
inputs/SILICIUM_UEFI.fd and inputs/firmware-audit.json. The builder receives the
captured FD snapshot. Independent unpacking compares the container with the
captured in-memory FD bytes, and the report references the saved audit snapshot.
The original paths are retained only as provenance. Inputs/FD and boot binaries
remain private; they must not be included in a public source bundle.
